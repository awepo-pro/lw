Covers lw v2.35.0 · 2026-10-06

Learn lw by doing

You start with sources — an article, a paper, a saved chat — and end with a small, cross-linked markdown wiki where every claim cites where it came from. lw is the compiler in the middle. An agent proposes the pages, and you decide what lands.

How to use this page Each lesson has a goal, the commands, what you should see, and a short check at the end. Open a terminal next to it and type along. Mark a lesson done when you've run it. Your progress is saved in this browser only. The terminal output shown here comes from real runs (see tutorial.md). Long output is trimmed, and trims are marked with ….
Which lw is this page for? (v2.35.0, and what changed since v2.30.0)

This page was checked against lw v2.35.0. Run lw version. If yours is older, some behaviour below won't match. If it's newer, trust lw --help where they disagree.

Changes since the last edition of this page (v2.30.0):

  • v2.35.0: an ingest that adds to an already-open changeset now says joined changeset … instead of opened (lesson 3).
  • v2.34.0: dropping or restoring a hunk in Review puts the text back exactly where it was, byte for byte. A frontmatter change is always its own hunk (lesson 4).
  • v2.33.0: the agent can't repeat a read whose answer it already has (lesson 3).
  • v2.32.0: cleaner staged pages. An echoed section heading is stripped, and a cited raw source is added to sources: (lesson 3).
  • v2.31.0: evaluation tooling only. Nothing you type changes.

00The mental model

Goal: know the two rules that explain every design choice in lw, before you type anything.

1 · The agent gets no filesystem

Its tool list has no write, edit, delete or bash. They aren't blocked. They're simply not offered. The only way the agent can change anything is through stage.* tools, which check each change and add it to a buffer.

2 · Nothing lands without your review

Every proposal goes into a changeset that you review hunk by hunk. Rejections are journalled too, so the history shows what the agent tried, not just what got in.

Everything else follows from these two rules. One loop runs again and again:

TermMeaning
VaultA directory with a SCHEMA.md. lw walks up from your current directory to find the nearest one, or you pass --vault <dir>.
raw/Ingested sources. Written once, never changed. Every claim cites back into here.
wiki/Reviewed pages: entities/, concepts/, comparisons/, queries/.
ChangesetOne reviewable unit of proposed ops (create_page, patch, rename, …). Only one can be open at a time.
SessionThe recorded agent conversation that produced a changeset. They share one id.
JournalThe append-only event log (.llmwiki/journal.ndjson) that lw log reads.
Check: the agent wants to fix a typo in a page. How does it do that?

It calls a stage.* tool (for example stage.patch_page). That adds a proposed op to the open changeset. The page on disk doesn't change until you review and commit.

01Install & connect a provider

Goal: a working lw binary that can reach a model with tool calling.

Install

# from source
git clone https://github.com/awepo-pro/lw && cd lw
make build                     # → ./lw

# or with Go 1.25.8+
go install github.com/awepo-pro/lw/cmd/lw@latest

# or Homebrew / Nix
brew install awepo-pro/tap/lw
nix profile install github:awepo-pro/lw
$ lw version
lw v2.35.0

The version comes from the release tag the binary was built from, so a bug report can name the exact build.

Point it at a model

lw sends requests in the plain OpenAI chat-completions format and defaults to DeepSeek. lw config shows what lw will actually use:

$ lw config
llm.base_url               = https://api.deepseek.com/v1   (default)
llm.model                  = deepseek-v4-flash   (default)
llm.api_key                = env:DEEPSEEK_API_KEY (missing)   (default)
llm.temperature            = 0.2   (default)
llm.max_tokens             = 32768   (default)
llm.limits.max_tool_rounds = 24   (default)
llm.limits.context_tokens  = 96000   (default)
…
The key is a reference, not a value. The config file stores env:DEEPSEEK_API_KEY (or keyring:NAME), and lw reads the variable only when it needs it. If you paste a literal key, lw rejects it with a warning. The key never shows up in output, in the config file, or in the vault. 
export DEEPSEEK_API_KEY=sk-...

# another OpenAI-compatible provider? set both together:
lw config set llm.base_url https://api.deepseek.com/v1
lw config set llm.model    deepseek-v4-flash
lw config set llm.api_key  env:MY_PROVIDER_KEY   # if your variable has another name

# end-to-end check: resolves the key, calls the model, confirms tool calling
lw config --probe
The #1 setup mistake llm.base_url must be an OpenAI-compatible /v1 endpoint. https://api.deepseek.com/anthropic looks fine, but every request to it returns a 404.

A healthy setup, as shown by lw doctor:

✓ config   api_key env:DEEPSEEK_API_KEY (set) · model deepseek-v4-flash @ https://api.deepseek.com/v1
✓ provider deepseek-v4-flash reachable, tool calling ok (1568ms)
Try it
Unset the key (unset DEEPSEEK_API_KEY) and run lw config --probe. It fails right away and tells you what to fix, without making a network call. Export the key again before you continue.

02Create a vault

Goal: an empty but valid vault, and a picture of what each file is for.

$ mkdir ml-wiki && cd ml-wiki
$ lw init --schema ml-systems
initialized vault in /home/you/ml-wiki
  domain           ml-systems
  tags             10 (10-20 recommended)
  files            SCHEMA.md, index.md, log.md, curator-memory.md, .gitignore
  directories      raw/{articles,papers,transcripts,assets}, wiki/{entities,concepts,comparisons,queries} (8 of 8 created)
  engine           .llmwiki/ (staging engine state)
next: lw config — point lw at a provider, then lw ingest <url> to add the first source

If you leave out --schema, init asks you for the domain, the tag list, and page-type conventions.

PathWhat it is
SCHEMA.mdThe domain and its 10–20 tags. Every page's tags: must come from this list.
index.mdCatalog of every page, one line each, organized in sections. The engine keeps it in sync.
log.mdAppend-only log for humans. Rotates at 500 entries.
curator-memory.mdThe agent's standing editorial preferences. It's a normal page, so you can edit it.
raw/…Ingested sources, written once and never changed.
wiki/…Reviewed pages, one directory per page type.
.llmwiki/Engine state: object store, changesets, journal, search index, transcripts. Listed in .gitignore. Deleting it loses history, not your notes.
$ lw status
0 pages · 0 raw · 10 tags
lint: 0 errors, 0 warnings, 0 info
no open changeset
$ lw lint
clean
Check: you're in ml-wiki/wiki/concepts/. Does lw status work?

Yes. lw walks up to the nearest ancestor that contains SCHEMA.md. Only init doesn't need to be inside a vault.

03Ingest your first source

Goal: turn one article into proposed pages, and understand what was proposed vs. what was written.

lw ingest ~/Downloads/kv-cache-explained.md   # a local file
lw ingest https://example.com/some-post        # or a URL
lw ingest ~/notes/                             # or a folder (.md .txt .html .pdf)

lw first converts each source to fixed markdown. If a path or URL is bad, the whole command fails before any changeset is opened. Then the agent reads the source, SCHEMA.md, index.md, and recent log.md, and proposes pages. To keep it writing instead of browsing, an ingest may read at most 6 existing wiki pages between two staged changes; a 7th read is refused until it stages something. It also can't repeat a read whose answer is still in its context, so it doesn't spend rounds looking at the same page twice. A real run that took about three minutes ends like this:

opened changeset cs-92c7d850b461792a: ingest ~/Downloads/kv-cache-explained.md (4 op(s))
  op1 ingest_source raw/articles/kv-cache-explained.md
  op2 create_page wiki/concepts/kv-cache.md
  op3 create_page wiki/concepts/autoregressive-decoding.md
  op4 create_page wiki/queries/reducing-kv-cache-memory.md
Nothing has been written yet. op1 is always the immutable copy of your source. It records the original source_url and a sha256 of the body, which lw later uses to detect drift. Every create_page after it can only cite that source, because it's the only thing the agent has read.

If a changeset is already open (say, from an Ask turn), the ingest adds to it instead of opening a second one, and the first line says so: joined changeset cs-… rather than opened changeset cs-….

Two small repairs happen as pages are staged, and the agent is told about each one. If a section edit repeats the section's own heading (## Trade-offs inside the Trade-offs section), the duplicate heading is removed. If a page's body cites a raw/ source that its sources: frontmatter doesn't list, the source is added. Both used to show up as lint warnings after an ingest.

Limits and dry runs

A single ingest is capped at 10 files and 75% of the context budget in bytes (282 KB at the default context_tokens = 96000). The agent still needs room to read back what it wrote. If you go over the cap, nothing is opened, and the error names the largest file so you know which one to split out. Sources the vault already holds are skipped before anything else happens.

$ lw ingest --dry-run ~/notes/
within limits: 3 files, 8 KB (limit 10 files, 282 KB)

--dry-run extracts every source and prints the result, but makes no changeset and no model call. URLs are still downloaded, because their size can't be checked otherwise.

Try it
Run lw ingest --dry-run on a folder of your own notes. Then ingest one small article for real, and run lw diff --op op1 to see the frontmatter lw added to the raw copy.

04Review the changeset

Goal: read exactly what would land, before it lands.

While a changeset is open, lw status counts only committed content. "0 pages" means nothing has landed yet, not that nothing happened:

$ lw status
0 pages · 0 raw · 10 tags
lint: 0 errors, 0 warnings, 0 info
open changeset cs-92c7d850b461792a: ingest ~/Downloads/kv-cache-explained.md (4 op(s), 0 stale; schema=pass lint=pass orphans=0 broken_links=0)
$ lw diff --stat
wiki/concepts/autoregressive-decoding.md | +30 -0
wiki/concepts/kv-cache.md | +38 -0
wiki/queries/reducing-kv-cache-memory.md | +34 -0
index.md | +5 -0
raw/articles/kv-cache-explained.md | +27 -0
5 file(s) changed, 134 insertion(s)(+), 0 deletion(s)(-)
CommandShows
lw diff --statOne line per file
lw diffFull unified diff, one hunk per changed section
lw diff --op op3Just one operation's files
lw lintLint on the projected tree, which catches problems before you commit

The TUI's Review screen (lesson 7) shows the same diff, plus two things a plain diff lacks: the agent's rationale for each change, and its provenance back into raw/.

Each hunk records the line where it starts, and it's applied the way patch applies a hunk. When you drop a hunk and restore it later, the page comes back byte for byte. A change to the frontmatter (the block between the --- lines) is never in the same hunk as a change to the body, so you can drop one and keep the other.

A stale op is one that was proposed against a file that has changed on disk since. lw won't apply it on top of your edit.

05Commit — or throw it away

Goal: land the pages, and know the two safety checks a commit runs.

$ lw commit -m "first pages from kv-cache-explained"
committed 000001
$ lw status
3 pages · 1 raw · 10 tags
lint: 0 errors, 0 warnings, 0 info
no open changeset

A commit is refused if…

  • a target file changed on disk since the op was proposed (the op is stale), or
  • it would leave lint with more errors than the last commit. --force overrides this, and the override is itself recorded in the journal.

There's no lw reject command. To throw a changeset away, discard it:

lw doctor --discard-changeset    # or press X on the TUI's Review screen

Nothing is deleted. The buffer moves to changesets/rejected/, and lw log --rejected shows it afterwards.

Lint severities Only an error makes lw lint exit non-zero. warn and info don't. A single-source page with confidence: low produces an info finding. That's normal and means "find a second source when you can", not "fix this now". There are 18 checks in total; see vault-schema.md.
Check: you hand-edited kv-cache.md while a changeset patching it was open. What happens at commit?

The op is stale and the commit is refused, so your edit is never silently overwritten.

06Ask questions

Goal: get cited answers from your own pages, and keep the good ones.

$ lw query "What is the KV cache, and why does per-token cost drop from O(n) to O(1) during decoding?"
The **KV cache** stores the key and value projections a transformer computes during decoding, so
each new token only computes attention *against* the cached keys and values instead of recomputing
them for the whole prefix. ^[raw/articles/kv-cache-explained.md] …

lw query is read-only. It never opens or leaves behind a changeset. Each claim ends with a marker that points at the raw evidence, ^[raw/…], with p.N added when the source is a paper with page anchors. If you ask about something you haven't ingested, the curator says so under Not from your vault: instead of making up a citation.

Keep an answer

In the TUI's Ask screen, an answer that cites the vault (it contains a ^[raw/…] or ^[wiki/…] marker) can be saved with ctrl+s. That stages a wiki/queries/ page, which you review like any other change. An answer with no vault citation can't be saved: "this answer cites no vault source; nothing to save".

Web lookup (optional)

Configure Tavily and the curator gets a 19th tool, web.search. When you don't configure it, the tool isn't offered at all. A search result only becomes a source after it's ingested with stage.ingest_source, and it goes through review like everything else.

# config.toml
[web]
api_key = "env:TAVILY_API_KEY"

# shell
export TAVILY_API_KEY=tvly-...

07The TUI

Goal: do the whole ask → review → commit loop without leaving the terminal UI.

Run lw with no command (or lw tui). It needs a terminal of at least 80×24. tab cycles through five screens:

Review → Ask → Lint → Log → Browse   (wrapping back to Review)

The header shows the vault counts and the open changeset (cs-1c86cb · 1 op · checks ✓). The footer always lists what the current screen's keys do. Press ? for every key.

Ask, then Review

Type a request and press enter. If no changeset is open, the turn opens one (ask: <your question>). If the turn stages nothing, lw discards that changeset for you. While you're on Ask, q and ? type into the message box, so quit with ctrl+c.

 ml-wiki   Review  Ask  Lint  Log  Browse    3 pages · 1 raw · 0 lint   cs-fd447f · 1 op · checks ✓
╭ Transcript — cs-fd447f ─────────────────────────────────────────── ↑ 28 earlier ╮
│ ▸ stage.close {}  → changeset cs-fd447f752de3e221                               │
│ assistant                                                                       │
│ Done — one staged patch, nothing else in the changeset.                         │
│ …                                                                               │
│ done · 5 rounds                                                                 │
╰─────────────────────────────────────────────────────────────────────────────────╯
╭ Message ────────────────────────────────────────────────────────────────────────╮
│ › █ Ask about the wiki…                                                         │
╰─────────────────────────────────────────────────────────────────────────────────╯
 enter send  ↑/↓ select tool call  ctrl+r review  tab screen  ? help

Press ctrl+r to jump to Review. The Ops panel on the left lists operations with a state glyph. The Diff panel on the right shows each op's rationale and provenance above its hunks:

GlyphOp state
●untouched
◐some hunks dropped
✗every hunk dropped
!stale. y, n and A refuse to act on it

Keys worth memorizing

Lint, Log, Browse

  • Lint: findings listed by severity. enter opens the page in Browse.
  • Log: journal events. f cycles the filter (all → accepted → rejected → agent → human). r reverts the selected commit into a new changeset.
  • Browse: the page tree. / finds a page, h/l collapse or expand a folder, o opens a cited PDF at the cited page.

Most keys can be rebound in ~/.config/lw/hotkeys.toml. See hotkeys.md.

Reading a conversation back

Every agent conversation is saved under the changeset it opened, and stays after commit or reject:

$ lw session list
ID         STATE      STARTED               RECORDS  BYTES
cs-fd447f  open       2026-09-16T12:00:06Z  10       15379
cs-bfa09e  rejected   2026-09-16T11:55:44Z  10       16158
cs-614c83  committed  2026-09-16T11:51:12Z  17       44643

$ lw session show fd447f --plain     # full tool args + results; --thinking, --json
$ lw trace                           # per-turn traces; lw trace show <ref> to inspect one
Try it
On Ask, type: "Stage one patch only: add a short Trade-offs section to wiki/concepts/kv-cache.md, per the ingested source." Press ctrl+r, then p to preview the page, p again to go back to the diff, and C to commit.

08History & undo

Goal: find out what happened, and roll back with the same review you'd give any change.

$ lw log --limit 20
2026-09-15T20:20:04Z changeset_opened changeset=cs-92c7d850b461792a actor=agent message="ingest ~/Downloads/kv-cache-explained.md"
2026-09-15T20:20:23Z op_proposed changeset=cs-92c7d850b461792a op=op1 actor=agent paths=raw/articles/kv-cache-explained.md
…
2026-09-15T20:25:55Z commit_end changeset=cs-92c7d850b461792a commit=000001 actor=agent message="first pages from kv-cache-explained" data={"lint_errors":0,"lint_warns":0}

Filters: --agent, --rejected, --limit N, --page <path>, --since <date>.

Revert opens a changeset, it doesn't write

$ lw revert 000001
opened cs-c5b709e6ddbd1832: revert of 000001 (skipped: index.md, raw/articles/kv-cache-explained.md)
skipped: index.md
skipped: raw/articles/kv-cache-explained.md
  • raw/ is skipped because it's immutable. A revert undoes the pages a source produced, never the source itself.
  • Reverted pages become retraction stubs, so links and index.md entries that point at them still resolve.

Then lw commit -m "revert 000001", or change your mind with lw doctor --discard-changeset.

Only one changeset is open at a time Ingest, Ask and lint --fix add their ops to the open changeset, and you review and commit them together. lw revert is the exception: it refuses while a changeset is open, so commit or discard that one first.

09Keeping the vault healthy

Goal: know where to look first when something seems wrong.

$ lw doctor
lw doctor — /home/you/ml-wiki
✓ index    0 document(s) indexed in .llmwiki/index.gob
✓ objects  no objects referenced yet (no open changeset, no snapshot)
✓ journal  0 event(s) parse cleanly
✓ recovery no interrupted apply
✓ lock     no lock held
- git      skipped: not a git repository
✗ config   api_key env:DEEPSEEK_API_KEY (missing) · model deepseek-v4-flash @ https://api.deepseek.com/v1
  fix: export DEEPSEEK_API_KEY, or point llm.api_key at another variable with lw config set llm.api_key env:NAME
- provider skipped: api_key did not resolve: config: environment variable DEEPSEEK_API_KEY is not set
1 of 8 check(s) failed
FlagUse when
--unlockA stale writer lock remains after a crash
--rebuild-indexSearch looks wrong. The index is a cache, so rebuilding is always safe
--discard-changesetThrow away the open changeset (it's kept as rejected)
--jsonScripting

Recovery, honestly: each file is written atomically, but a commit across many files isn't. If a commit is interrupted, lw doctor shows which files were applied and which are pending, and finishes the commit forward from the object store. You never have to repair it by hand.

Let the agent fix lint: lw lint --fix sends findings to the agent one page at a time. The fixes are staged as a changeset for you to review.

10Notes, PDFs, MCP

Goal: know the side doors: quick capture, papers, and other agents.

Quick notes (no LLM, no review)

lw note -m "check whether paged attention changes the KV-cache trade-off"
lw note                 # compose in $VISUAL / $EDITOR
lw note list -n 10

Notes go into notes/, outside the wiki. They're never indexed or snapshotted. Think of it as an inbox for thoughts you'll turn into sources later.

PDFs

uv tool install docling==2.130.0     # one-time; ~6 GB, runs CPU-only
lw ingest paper.pdf
lw config set open.pdf "papers -i {page} {file}"   # or: mupdf {file} {page}
  • Citations can name the physical page: ^[raw/papers/leviathan-2023.md p.12]. In Browse, o opens the PDF at that page.
  • Scanned or image-only PDFs are refused (no OCR). Whole books are too big for one ingest, so ingest a chapter at a time.
  • Converted PDFs are cached in .llmwiki/cache/extract/. The cache is safe to delete.

Use lw from another agent (MCP)

{
  "mcpServers": {
    "lw": { "command": "lw", "args": ["mcp"] }
  }
}

This exposes the same 18 vault tools, plus web.search when it's configured. lw mcp itself needs no API key, because the client brings its own model. On the wire, dots become underscores (wiki.search → wiki_search). See tools.md.

11Troubleshooting

Goal: recognise the common failures by their symptoms.

SymptomCause → fix
Provider returns 400 / 404 / "not found"llm.base_url isn't an OpenAI-compatible /v1 endpoint. Run lw config set llm.base_url …/v1, then lw config --probe.
env:DEEPSEEK_API_KEY (missing)Export the variable in this shell, or point the reference at another one with lw config set llm.api_key env:NAME.
lw revert: "a changeset is already open"Revert needs a clean slate. Run lw status → lw diff, then commit, press X, or run lw doctor --discard-changeset. (Ingest, Ask and lint --fix join the open changeset instead.)
Ingest stops: output limit reachedThe default is 32768. If your config sets it lower, raise it with lw config set llm.max_tokens 32768 (lw doctor warns below 16000). Thinking models use a lot of it.
Agent refuses to write a pageIt won't write a claim it can't cite. Ingest a source first. Pages also need at least two outbound [[wikilinks]].
warning: lint regresses after ingestThe changeset is still open. Review it with lw diff, drop the bad hunks, or commit with --force (which is recorded in the journal).
